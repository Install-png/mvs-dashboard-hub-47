## Що додаємо

Дві великі функції:

### 1. Призначення адмінів на регіон/службу + email-розсилка
- Нова таблиця `admin_assignments` — прив'язка користувача до регіону (oblast) та служби (ДСНС / Поліція / Нацгвардія / Медики).
- У панелі ролей: для кожного користувача можна обрати регіон(и) та службу(и) відповідальності.
- При створенні/оновленні інциденту (статус `Critical` або новий) — DB-trigger ставить подію в чергу, edge function `notify-incident-responders` знаходить усіх адмінів, що відповідають за `region_id` + `service`, та шле їм email-звіт із скріном/даними інциденту (хто, де, що, які служби залучені, ETA).
- Email через Lovable Emails (потрібно домен). До налаштування домену — fallback: показувати тост + запис у `notifications` таблицю + кнопка "Налаштувати email-домен".

### 2. Розподіл сил і ресурсів + резерв
- Нова таблиця `resources` — одиниці техніки/спорядження (тип: автодрабина, АЦ, реанімобіль, БТР тощо), `unit_id` (підрозділ), `region_id`, `city`, координати, статус (`available` / `deployed` / `maintenance` / `reserve`), кількість.
- Нова таблиця `units` — підрозділи (назва, служба, регіон, місто, координати).
- Нова сторінка **"Ресурси"** в сайдбарі:
  - Список усіх підрозділів та їх техніки.
  - Форма додавання ресурсу/резерву.
  - Перемикач `reserve` — позначити одиницю як резервну.
- В інциденті новий блок **"Розрахунок ресурсів"**:
  - Користувач обирає необхідну техніку (напр. "автодрабина 1 шт").
  - Алгоритм:
    1. Шукає підрозділ у тому ж місті з `available` ресурсом.
    2. Якщо немає — обчислює найближчий підрозділ по haversine (координати інциденту ↔ координати підрозділу), де ресурс `available`.
    3. Повертає список: підрозділ, відстань (км), ETA (км / 60 км·год · 60 хв), що саме направляється.
  - Кнопка "Направити" — створює запис у `resource_dispatches` (incident_id, resource_id, dispatched_at, eta_minutes), змінює статус ресурсу на `deployed`.
- В дашборді — віджет "Дефіцит ресурсів": якщо <30% доступного по типу — попередження.

## Технічна частина

```text
DB:
  units(id, name, service, region_id, city, lat, lng)
  resources(id, unit_id, type, label, status, is_reserve, quantity, lat, lng)
  resource_dispatches(id, incident_id, resource_id, dispatched_at, eta_minutes, status)
  admin_assignments(id, user_id, region_id, service)
  notifications(id, user_id, incident_id, kind, sent_at, channel)

Edge functions:
  notify-incident-responders  -- trigger через DB webhook on incidents INSERT/UPDATE

Frontend:
  src/pages/ResourcesPage.tsx
  src/components/ResourceDispatcher.tsx    (всередині картки інциденту)
  src/components/AssignmentsAdmin.tsx      (у вкладці Ролі)
  src/hooks/useResources.tsx
  src/lib/distance.ts                      (haversine + ETA)
```

## Email-домен

Email-розсилка вимагає верифікованого домену. Перший крок — налаштування домену відправника через діалог Lovable Cloud. Після цього автоматично згенеруємо шаблон "Інцидент у вашій зоні відповідальності" і підключимо тригер.

## Порядок виконання

1. Міграція БД (4 нові таблиці + RLS + grants).
2. Сторінка "Ресурси" + хук + сайдбар.
3. Блок розподілу ресурсів у деталях інциденту (haversine).
4. UI призначень адмінів (регіон/служба) у вкладці Ролі.
5. Налаштування email-домену → шаблон → edge function → тригер.

Підтвердіть план — і починаю з кроків 1–4 одразу, а для email-розсилки покажу діалог налаштування домену.
